Here’s a complete breakdown of the **8 major DNS attacks**, with how they **work**, how to **recognize them**, and how to **stop/block** them. This is ideal for security-minded sysadmins, ecommerce infrastructure professionals, or even advanced merchandisers managing their own stacks.

---

## 🛡️ 1. DNS Spoofing (Cache Poisoning)

### How It Works:

An attacker injects a forged DNS response into a resolver’s cache, causing it to return incorrect IP addresses, usually leading to phishing or malware sites.

### Recognize:

- DNS records pointing to suspicious or incorrect IPs.
    
- SSL/TLS certificate warnings.
    
- Inconsistent TTLs or responses from different resolvers.
    

### Stop/Block:

- Enable **DNSSEC** (Domain Name System Security Extensions) to authenticate responses.
    
- Configure resolvers to **only accept responses to questions asked** (reject unsolicited responses).
    
- Use **DNS resolver hardening** (e.g., Unbound or BIND with strict settings).
    

---

## 🛡️ 2. DNS Tunneling

### How It Works:

Used for data exfiltration or command-and-control channels. Data is encoded into subdomains, allowing malware to "tunnel" through port 53.

### Recognize:

- High volumes of DNS queries to a specific domain.
    
- Domains with unusual or base64-like subdomains.
    
- Long query names with high entropy.
    

### Stop/Block:

- Monitor with **Zeek** or **Suricata** for entropy anomalies.
    
- Implement **deep packet inspection** (DPI) or DNS filtering.
    
- Block known tunneling domains (e.g., via **RPZ zones** or threat feeds).
    

---

## 🛡️ 3. DNS Amplification (DDoS)

### How It Works:

Attackers send DNS queries with a spoofed source IP (the victim’s IP) to open resolvers, which respond with large payloads, overwhelming the target.

### Recognize:

- Your DNS server sending large amounts of unsolicited traffic.
    
- Unusually high outbound DNS traffic.
    
- Upstream provider flags abusive behavior.
    

### Stop/Block:

- Disable recursion for unknown IPs (i.e., **disable open resolvers**).
    
- Rate-limit DNS responses (`rate-limit` in BIND or `ip-ratelimit` in Unbound).
    
- Use a **DDoS mitigation service** (e.g., Cloudflare, Akamai).
    

---

## 🛡️ 4. Domain Hijacking

### How It Works:

An attacker gains unauthorized control of a domain (via registrar account compromise), redirecting DNS records to malicious destinations.

### Recognize:

- WHOIS changes or unexpected nameservers.
    
- DNS record changes you didn’t make.
    
- Users redirected to strange or unsafe sites.
    

### Stop/Block:

- Use **registrar lock**, **registry lock**, and **2FA** on domain registrar accounts.
    
- Monitor with **Certificate Transparency logs** and WHOIS watch tools.
    
- Use **DNSSEC** to prevent impersonation of DNS records.
    

---

## 🛡️ 5. DNS Rebinding

### How It Works:

A browser is tricked into accessing internal IPs (like `127.0.0.1` or `192.168.x.x`) through malicious DNS tricks, bypassing same-origin policies.

### Recognize:

- Client browsers making requests to internal IPs.
    
- Suspicious JavaScript activity via DevTools or logs.
    
- Unusual DNS TTL behaviors (short TTLs, then switching to internal IPs).
    

### Stop/Block:

- Use **browser DNS rebinding protection** (some browsers block private IP targets).
    
- Configure internal apps to **reject requests by Host header**.
    
- Block external DNS resolving to internal ranges (RFC 1918) at the firewall.
    

---

## 🛡️ 6. Typosquatting / Lookalike Domains

### How It Works:

Attackers register domains like `gooogle.com` or `amaz0n.co` to trick users into visiting them. Often used in phishing or brand impersonation.

### Recognize:

- SSL certs issued for suspicious lookalike domains.
    
- Users visiting fake login pages.
    
- Typos in emails or referral logs.
    

### Stop/Block:

- Monitor via **Certificate Transparency** logs.
    
- Use **brand protection** services (e.g., MarkMonitor, DomainTools).
    
- Preemptively register lookalikes if critical.
    

---

## 🛡️ 7. NXDOMAIN Attack (DNS Flood)

### How It Works:

Flooding a DNS server with queries for nonexistent domains, overloading its cache and consuming CPU/memory.

### Recognize:

- Spike in queries with `NXDOMAIN` responses.
    
- Resolver logs flooded with failed lookups.
    
- Slow or crashing DNS service.
    

### Stop/Block:

- **Rate-limit** NXDOMAIN responses.
    
- Use **fail2ban** or similar to detect and ban abusive clients.
    
- Use a **local DNS cache with aggressive negative caching** (e.g., dnsmasq, Unbound).
    

---

## 🛡️ 8. Phantom Domain Attack

### How It Works:

Clients are tricked into repeatedly trying to resolve domains that respond very slowly or never respond, tying up resources.

### Recognize:

- DNS timeouts and retry storms.
    
- Log entries showing repeat lookups for the same "slow" domain.
    
- Resolver CPU spikes.
    

### Stop/Block:

- Configure resolver timeouts and max retries conservatively.
    
- Drop long-latency domains quickly.
    
- Monitor query response time with **dnstop** or **DNSPerf**.
    

---

## 🔒 General Best Practices

- ✅ Use **DNSSEC** everywhere possible.
    
- ✅ Prefer **reputable managed DNS** providers with DoS protection.
    
- ✅ Regularly **audit your DNS records** and TTLs.
    
- ✅ Monitor DNS logs with **SIEMs** (like Splunk, Graylog, or Wazuh).
    
- ✅ Harden your DNS software (disable recursion, implement ACLs, etc.).
